DESIGNING FOR FEELING

Actions, pace, and comfort.

Current interface and design reflection · updated November 16, 2026

01 / Intention and current prototype

Desktop Beomgyu is an unofficial photo-based companion intended to feel playful and comforting. This website lets visitors experiment with actions, pace, and Quiet comfort. The native Mac app is a separate download; the newest website controls and animation changes have not been added to that build.

02 / Inputs that combine

ControlStateResponse
Action radio buttonsStay, Walk, Run, Celebrate, HugOne action at a time.
Movement speed slider50% to 180%; default 100%Changes walking and running pace continuously. The percentage updates immediately.
Quiet comfort checkboxOn or offSlows walking/running further, slows Hug, and reduces celebration bounce.
Size radio buttonsTiny, Small, LargeScales the character.
Reset to Stay buttonInitial controlsRestores Stay, Small, Quiet comfort off, and 100% pace.

Try Run at 150%, then toggle Quiet comfort. The action, slider, and checkbox jointly determine how energetic the movement feels. The slider affects only Walk and Run.

action change → select behavior
slider input → update pace and percentage
checkbox change → apply comfort response

if action is Walk or Run:
  speed = baseSpeed × (slider / 100) × (quiet ? 0.55 : 1)
if reduced motion is preferred:
  stop wandering

Reset → Stay + Small + 100% + comfort off

03 / Structure and layout

Semantic HTML separates the preview, form controls, helper explanation, and download. Fieldsets, legends, and labels explain the input groups. CSS Grid creates two columns on desktop; tighter spacing and a sticky preview keep the character visible beside the taller controls. Tablet and mobile layouts stack the content. Focus outlines and the native slider support keyboard use.

The response card explains the selected action and comfort setting. The slider provides its own numeric feedback. The intent is to make experimentation understandable without crowding the preview.

04 / AI collaboration and revisions

The student supplied the concept, reference media, and detailed feedback. Codex helped implement HTML, CSS, JavaScript, photo preparation, and documentation. AI output was repeatedly challenged: the initial sideways walking, altered hug face, disconnected joints, incorrect arm layers, and same-side arm-leg motion did not match the intended experience.

The approved hug uses 20 original GIF frames with background masks. Walking and running use the existing photos with articulated limbs; the face is not regenerated during animation. Shared-edge arm meshes, corrected depth order, and opposite arm-leg timing were iterative responses to feedback. These photo animations remain experimental.

Feedback about readability led to larger labels, numbered steps, clearer state descriptions, and a speed slider. The slider combines with existing controls rather than adding an unrelated effect.

05 / Verification and limits

The slider was checked at its minimum and maximum, with Quiet comfort, and after Reset. Joint poses were inspected at several points in the stride. The revised desktop layout was checked while scrolling. These checks do not guarantee flawless motion on every device.

The website does not access, move, or delete files. Its Trash section explains the native app interaction. The complete Mac ZIP includes the older native app and all character assets; it requires Apple silicon and macOS 26 or later and is not notarized. ChatGPT integration is still an idea, not an implemented feature.

06 / Coursework and links

I learned that HTML structures the content while CSS controls layout and style. JavaScript functions and event listeners make the controls respond to combined states. I am still exploring how strongly the pace should change to feel calming or energetic without becoming distracting.
